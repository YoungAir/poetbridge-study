# PoetBridge 诗歌阅读试点采集站

这是一个静态网页，默认使用浏览器本地存储，不向任何服务器发送参与者答案。页面包含 4 首唐诗；参与者按匿名编号 P01–P10 分配到每首诗的基线/短诗桥接条件。每位参与者阅读 4 首，每个条件 2 首；10 个编号合起来，每首诗在两种条件下各出现 5 次。

## 诗作与桥接材料

| 编号 | 诗作 | 桥接参照 | 选择理由 |
| --- | --- | --- | --- |
| Tang_Baseline_130 | 逢雪宿芙蓉山主人 | 柳宗元《江雪》 | 短篇写景；共同的风雪意象可比较人物处境与情绪 |
| Tang_Baseline_099 | 汉江临眺 | 王维《终南别业》 | 山水视觉与虚实表现 |
| Tang_Baseline_045 | 金陵酒肆留别 | 王维《送元二使安西》 | 饮酒送别与离情表达 |
| Tang_Baseline_072 | 琴歌 | 白居易《琵琶行》 | 音乐场景、听者反应与静默描写 |

诗题、诗文、两条可见注释和 Q1–Q3 题目从项目冻结考卷中抽取；桥接诗句为预先指定的固定材料。实验条件为“同样的两条注释 + 一条参照诗句”，基线条件为“两条注释”。每题作答一次，不做前后测重复题，以减少记忆与练习效应。

## 本地试跑

从项目根目录运行：

```powershell
py -m http.server 4173
```

打开 `http://localhost:4173`。研究者管理页位于 `http://localhost:4173/researcher.html`，会显示每个编号对应的诗作条件矩阵和实际人数核对。参与者数据只存在于该浏览器来源的 localStorage；若同一设备顺序使用，记录会自动累积。若每人使用自己的设备，完成后下载 JSON，由研究者逐份导入管理页。

## GitHub Pages

本站已部署到 `https://youngair.github.io/poetbridge-study/`。向 `main` 分支提交后，`.github/workflows/pages.yml` 会自动发布当前目录。每位参与者自己的浏览器数据不会自动汇入仓库；GitHub Pages 只托管静态文件，没有写入数据库的能力。本版本采用参与者下载匿名 JSON、研究者导入汇总的方式。不要把包含参与者回答的 JSON/CSV 提交到公开 GitHub 仓库。

## 正式招募前

编辑 `study-config.js`：填写真实研究者联系渠道、经机构确认的伦理/审查说明，并把 `mode` 从 `preview` 改成 `live`。正式招募前还需按所在机构要求确定研究对象资格、知情同意文本、退出与撤回流程、数据保存位置和期限。当前页面仅接受 18 周岁及以上参与者；若计划招募未成年人，需先修改研究方案并取得适用的伦理与监护人同意，不能直接使用此版本。

编号 P01–P10 要由研究者一次性发放且不可重复。分配由编号固定计算，即便参与者各自使用不同设备也保持平衡。超过十人时分配模式循环重复，新增样本需要重新规划平衡表。

研究者导出的 CSV 每首诗一行，包含原文回答与空白 `score_Q1_0_to_3` 等列，供人工盲评后填分。不要让参与者在研究者页面查看或评分。
